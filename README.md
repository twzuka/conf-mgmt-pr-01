# Эмулятор командной оболочки

Консольный эмулятор оболочки UNIX-подобной ОС на Python.

Проект разработан в рамках практической работы № 1 по дисциплине «Конфигурационное управление».

- **Группа:** ИКБО-40-25
- **Вариант:** 13
- **Реализованы:** этап 1 — REPL, этап 2 — конфигурация.

## Требования

- Python 3.9 или новее.
- Windows или Linux.

Используется только стандартная библиотека Python. Установка дополнительных пакетов и сборка не требуются.

## Быстрый запуск

Все команды ниже выполняются из корня репозитория.

### Windows

```powershell
python src/main.py
```

Или через скрипт запуска в PowerShell:

```powershell
.\run.bat
```

### Linux

```bash
python3 src/main.py
```

Или через скрипт запуска:

```bash
./run.sh
```

После вывода конфигурации программа переходит в интерактивный режим. Введите команду и нажмите Enter. Для завершения используйте `exit`.

## Параметры запуска

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `--vfs-path PATH` | Путь к источнику виртуальной файловой системы | Не задан |
| `--prompt TEXT` | Текст приглашения к вводу | Формируется по данным ОС |
| `--script PATH` | Путь к стартовому скрипту | Не задан |

Все параметры необязательны. Относительные пути отсчитываются от каталога, из которого запущена программа.

Без `--prompt` приглашение имеет вид:

```text
username@hostname:current_directory$
```

При запуске программа выводит значения всех трёх параметров. Значение `None` означает, что параметр не передан.

### Пример со всеми параметрами

Windows:

```powershell
python src/main.py --vfs-path vfs.xml --prompt "demo> " --script scripts/startup.txt
```

Linux:

```bash
python3 src/main.py --vfs-path vfs.xml --prompt "demo> " --script scripts/startup.txt
```

Скрипты `run.bat` и `run.sh` также принимают эти параметры:

```powershell
.\run.bat --prompt "demo> " --script scripts/startup.txt
```

```bash
./run.sh --prompt "demo> " --script scripts/startup.txt
```

Значения с пробелами необходимо заключать в кавычки.

### Справка

```bash
python src/main.py --help
```

В Linux используйте `python3` вместо `python`.

## Команды эмулятора

| Команда | Текущее поведение |
|---|---|
| `ls [аргументы]` | Выводит имя команды и переданные аргументы |
| `cd [аргументы]` | Выводит имя команды и переданные аргументы |
| `exit` | Завершает работу эмулятора |

Пример интерактивного сеанса:

```text
demo> ls one.txt
Command: ls
Arguments: ['one.txt']
demo> cd documents
Command: cd
Arguments: ['documents']
demo> unknown_command
unknown_command: command not found
demo> exit
```

Неизвестная команда сопровождается сообщением об ошибке. После этого эмулятор продолжает работу.

Ввод разделяется на команду и аргументы по пробельным символам. Пустые строки не выполняют никаких действий. Обработка кавычек внутри команд эмулятора пока не реализована.

## Стартовый скрипт

Стартовый скрипт — текстовый файл в кодировке UTF-8. Каждая строка содержит одну команду эмулятора.

Файл `scripts/startup.txt` содержит демонстрационный сценарий:

```text
ls one.txt
unknown_command
cd documents
ls -l
exit
```

При запуске с параметром `--script` программа:

1. Выводит конфигурацию.
2. Читает и выполняет строки скрипта по порядку.
3. Показывает приглашение, выполняемую строку и результат команды.
4. После неизвестной команды выводит ошибку и продолжает выполнение.
5. Завершает работу при встрече `exit`.

Если скрипт закончился без `exit`, запускается интерактивный режим.

Если файл невозможно открыть или прочитать, выводится сообщение `Startup script error: ...`, после чего запускается интерактивный режим.

## Проверка работы

### Проверка параметров запуска

Системные скрипты запускают эмулятор с каждым параметром отдельно и со всеми параметрами вместе.

Windows, PowerShell:

```powershell
.\scripts\check_parameters.bat
```

Linux:

```bash
./scripts/check_parameters.sh
```

### Автоматические тесты

Windows:

```powershell
python -m unittest discover -s tests
```

Linux:

```bash
python3 -m unittest discover -s tests
```

Тесты проверяют разбор команд, формирование приглашения, команды-заглушки, параметры запуска, выполнение стартовых скриптов и поведение интерактивного режима.

## Текущие ограничения

- Путь к VFS принимается и выводится, но файловая система ещё не загружается. Загрузка XML и проверка его корректности относятся к этапу 3.
- Команды `ls` и `cd` остаются заглушками. Они не читают содержимое каталогов и не меняют текущий каталог. Их полноценная реализация относится к этапу 4.

# Эмулятор командной оболочки

Консольный эмулятор оболочки UNIX-подобной ОС на Python.

Проект разработан в рамках практической работы № 1 по дисциплине «Конфигурационное управление».

- **Группа:** ИКБО-40-25
- **Вариант:** 13
- **Реализованы:** этап 1 — REPL, этап 2 — конфигурация, этап 3 — VFS, этап 4 — основные команды.

## Требования

- Python 3.9 или новее.
- Windows или Linux.

Используется только стандартная библиотека Python. Установка дополнительных пакетов и сборка не требуются.

## Быстрый запуск

Все команды ниже выполняются из корня репозитория.

### Windows

```powershell
python src/main.py --vfs-path vfs/minimal.xml
```

Или через скрипт запуска в PowerShell:

```powershell
.\run.bat --vfs-path vfs/minimal.xml
```

### Linux

```bash
python3 src/main.py --vfs-path vfs/minimal.xml
```

Или через скрипт запуска:

```bash
./run.sh --vfs-path vfs/minimal.xml
```

После вывода конфигурации и загрузки VFS программа переходит в интерактивный режим. Введите команду и нажмите Enter. Для завершения используйте `exit`.

## Параметры запуска

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `--vfs-path PATH` | Путь к источнику виртуальной файловой системы | Обязательный параметр |
| `--prompt TEXT` | Текст приглашения к вводу | Формируется по данным ОС |
| `--script PATH` | Путь к стартовому скрипту | Не задан |

`--vfs-path` обязателен начиная с этапа 3. Остальные параметры необязательны. Относительные пути отсчитываются от каталога, из которого запущена программа.

Без `--prompt` имя пользователя и компьютера берутся из реальной ОС,
а путь показывает текущий виртуальный каталог (при запуске `/`):

```text
username@hostname:/virtual/current/directory$
```

При запуске программа выводит значения всех трёх параметров. Значение `None` означает, что параметр не передан.

### Пример со всеми параметрами

Windows:

```powershell
python src/main.py --vfs-path vfs/minimal.xml --prompt "demo> " --script scripts/startup.txt
```

Linux:

```bash
python3 src/main.py --vfs-path vfs/minimal.xml --prompt "demo> " --script scripts/startup.txt
```

Скрипты `run.bat` и `run.sh` также принимают эти параметры:

```powershell
.\run.bat --vfs-path vfs/minimal.xml --prompt "demo> " --script scripts/startup.txt
```

```bash
./run.sh --vfs-path vfs/minimal.xml --prompt "demo> " --script scripts/startup.txt
```

Значения с пробелами необходимо заключать в кавычки.

### Справка

```bash
python src/main.py --help
```

В Linux используйте `python3` вместо `python`.

## Команды эмулятора

| Команда | Поведение и поддерживаемые режимы |
|---|---|
| `ls [-a] [-l] [PATH ...]` | Имена по алфавиту; -a включает скрытые, -l показывает тип и размер |
| `cd [PATH]` | Смена виртуального каталога; без аргумента переход в / |
| `cd -` | Переход в предыдущий каталог с выводом его пути |
| `uptime` | Время работы эмулируемой ОС с запуска приложения, в формате HH:MM:SS |
| `cat FILE ...` | Вывод UTF-8-файлов без добавления переводов строки |
| `head [-n N / --lines=N] FILE ...` | Первые N строк; по умолчанию 10, N >= 0 |
| `exit` | Завершение сеанса, без аргументов |

`uptime` использует монотонные часы приложения, а не время работы компьютера.
Время одинаково отсчитывается при выполнении сценария и в REPL.
`ls -l` пока показывает тип (`d` для каталога, `-` для файла), размер в байтах
(для каталога 0) и имя. Опции `-a` и `-l` можно объединить в `-al`.
При нескольких путях `ls` показывает заголовок пути, `head` — заголовок файла.
После ошибки одного операнда остальные файлы обрабатываются.

Пути абсолютные (`/documents`) и относительные (`study/practice`).
Поддерживаются `.` и `..`, повторные `/`, `cd -`. Выше корня `/` перейти
нельзя. Проход через файл, например `hello.txt/..`, является ошибкой.
Реальный каталог ОС не меняется. Для имени, начинающегося с дефиса,
используйте `--`, например `cat -- -dash.txt`.

Пример интерактивного сеанса с `vfs/demo.xml`:

```text
demo> cd /documents/study/practice
demo> cat task.txt
Вариант 13
demo> cd /
demo> head -n 2 lines.txt
Строка 1
Строка 2
demo> cat missing
cat: missing: no such file or directory
demo> exit
```

Ошибки неизвестных команд, параметров и путей сообщаются пользователю;
сеанс продолжается. Пустые строки ничего не выполняют. Парсер разделяет
ввод по пробельным символам, как требует вариант 13. Кавычки, конвейеры,
перенаправления и подстановка переменных внутри эмулятора не реализованы.
`cat` и `head` требуют пути: чтение стандартного ввода не поддерживается.
Двоичные файлы загружаются в VFS, но текстовые команды требуют UTF-8.

## Стартовый скрипт

Стартовый скрипт — текстовый файл в кодировке UTF-8. Каждая строка содержит одну команду эмулятора.

Файл `scripts/startup.txt` содержит демонстрационный сценарий:

```text
ls
ls hello.txt
ls -l
cd
cd documents
cd /documents/study/practice
ls task.txt
unknown_command
ls
exit
```

При запуске с параметром `--script` программа:

1. Выводит конфигурацию.
2. Загружает VFS в память, затем читает и выполняет строки скрипта по порядку.
3. Показывает приглашение, выполняемую строку и результат команды.
4. После неизвестной команды выводит ошибку и продолжает выполнение.
5. Завершает работу при встрече `exit`.

Если скрипт закончился без `exit`, запускается интерактивный режим.

Если файл невозможно открыть или прочитать, выводится сообщение `Startup script error: ...`, после чего запускается интерактивный режим.

## Проверка работы

### Проверка параметров запуска

Системные скрипты проверяют обязательный путь VFS, пользовательское приглашение, стартовый скрипт и сочетание всех параметров. Используются minimal.xml, files.xml и nested.xml.

Windows, PowerShell:

```powershell
.\scripts\check_parameters.bat
```

Linux:

```bash
./scripts/check_parameters.sh
```

### Проверка загрузки VFS и ошибок

Windows, PowerShell:

```powershell
.\scripts\check_vfs.bat
```

Linux:

```bash
sh scripts/check_vfs.sh
```

Скрипты запускают минимальную VFS, VFS с несколькими файлами и VFS с тремя вложенными папками. Затем проверяют некорректный XML, некорректный base64, отсутствующий файл, отсутствие обязательного параметра и отсутствующий стартовый скрипт. Сообщения об ошибках в этих проверках ожидаемы.

Коды завершения эмулятора: `0` — нормальное завершение, `1` — ошибка загрузки VFS, `2` — ошибка параметров запуска. Ошибка чтения стартового скрипта сохраняет поведение этапа 2: вывод сообщения и переход в REPL.

Скрипты проверок показывают результаты запусков; их собственный код завершения не является общим результатом всех проверок.

## Формат VFS

Формат XML выбран для этого проекта. Методичка требует XML и base64 для двоичных данных, но не задаёт имена тегов.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
    <directory name="documents">
        <file name="notes.txt" encoding="text">Первая строка
Вторая строка</file>
    </directory>
    <file name="data.bin" encoding="base64">AAEC/w==</file>
</vfs>
```

- `<vfs>` — корневая папка `/` без атрибутов.
- `<directory name="...">` — папка; внутри могут быть папки и файлы.
- `<file name="..." encoding="text">` — текстовый файл. Если encoding не указан, используется text.
- `encoding="base64"` — содержимое двоичного файла; при загрузке декодируется в байты.
- Имена внутри одной папки должны быть уникальными. Пустые имена, `.` и `..`, разделители `/` и `\` не допускаются.
- Текст сохраняется с переносами и пробелами внутри `<file>`. Специальные символы XML нужно экранировать: например, `&amp;` и `&lt;`.
- Пустая VFS допустима и описывается как `<vfs/>`.

Папки хранятся как объекты Directory со словарём children, файлы — как объекты File с содержимым в байтах. Загрузчик только читает XML: не распаковывает VFS и не изменяет источник.

При успехе выводится, например, `VFS loaded: 3 directories, 2 files`. Корневая папка в счётчик не входит. Этот вывод помогает проверить загрузку VFS. Начиная с этапа 4 команды работают с загруженной VFS.

Если файл отсутствует, XML повреждён или структура не соответствует выбранному формату, программа выводит `VFS error: ...` и завершается до выполнения стартового скрипта и REPL.

## Ветки и этапы

Этапы разработки сохранены отдельными Conventional/Scoped-коммитами.
`stage-2` хранит конфигурацию; `stage-3` — VFS с исправленным оформлением;
`stage-4` — основные команды. Следующий этап выполняется в `stage-5`.
Для защиты исторического этапа 1 доступен коммит `93cbe53`.

Архивы, двоичные файлы, кэш Python, окружение, артефакты сборки и настройки
редактора в репозиторий не включаются. Двоичный пример хранится как base64.
Ограничения Python: 80 символов в строке, 40 строк в функции, 7 аргументов,
цикломатическая сложность не выше 10; функции документируются docstring.

## Функции приложения

### src/commands.py

| Функция | Назначение |
|---|---|
| `list_entries(node, path, show_all)` | Возвращает отсортированные элементы каталога или сам файл. |
| `format_entry(name, node, long_format)` | Форматирует имя либо тип, размер в байтах и имя узла. |
| `command_ls(state, args)` | Выводит каталог или файл; поддерживает -a, -l и несколько путей. |
| `command_cd(state, args)` | Меняет каталог; без пути переходит в /, cd - возвращает предыдущий. |
| `read_text(state, path)` | Возвращает UTF-8-текст файла; каталоги и двоичные данные запрещены. |
| `first_lines(text, count)` | Возвращает первые строки, считая разделителем только символ LF. |
| `output_files(state, paths, line_count)` | Выводит доступные текстовые файлы, сохраняя сведения об ошибках. |
| `command_cat(state, args)` | Выводит содержимое одного или нескольких UTF-8-файлов. |
| `command_head(state, args)` | Выводит первые 10 строк или число строк из -n/--lines. |
| `command_uptime(state, args)` | Выводит время работы эмулируемой ОС с момента запуска приложения. |
